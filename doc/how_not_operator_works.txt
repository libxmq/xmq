How the not operator !name works in xmq's ixml engine
=====================================================

When the grammar is read, !name is turned into an empty marker rule. While
parsing, the engine checks the input ahead against the alternatives of the
rule name, without consuming anything. There are three stages.

1. Reading the grammar (src/main/c/parts/ixml.c)
------------------------------------------------

parse_ixml_not reads the !. If a name follows, add_not_rule_nonterminal builds
the name |!N + rule name, eg |!Nkw_else. It then:

  - creates an empty rule with that name (no right hand side),
  - adds it as a nonterminal and puts it where the !kw_else stood,
  - records it in ixml_non_terminals_map, so every !kw_else in the grammar
    shares one |!Nkw_else.

The grammar of tests/ixml_not_035_not_rule_sequence.test therefore ends up
internally as:

  if   = -'if ', cond, stmt, (-'else ', stmt | |!Nkw_else).
  call = |!Nkw_else, ['a'-'z']+, -';'.
  |!Nkw_else = .                 { empty, only a marker }
  kw_else = 'else', ~['a'-'z'].  { unchanged, also usable as a normal rule }

Strings and charsets work the same way with other prefixes: !'in' becomes
|!Sin and ![L] becomes |![L].

2. Checking the rule (check_not_rule_nonterminals in ixml.c)
------------------------------------------------------------

Once the whole grammar is read, each |!N... rule is checked. The rule after the
! must be defined, and not_rule_kind decides whether it is allowed:

  kind 1  Every alternative is exactly one character: a character, a charset,
          or a call of a kind 1 rule. Eg namechar in test 032:
            -namechar = ['a'-'z'; '0'-'9'; '-'].

  kind 2  A single alternative that is a fixed sequence of characters:
          strings, charsets, or calls of kind 1 or 2 rules. Eg:
            -kw_else = 'else', ~['a'-'z'].

  kind 3  Several alternatives, each a fixed sequence. Eg wordish in test 033,
          or a keyword list:
            -wordish = letter | digit | '_'.
            -kw = 'if', ~[L] | 'else', ~[L].

Repetitions, options and empty alternatives are rejected with "the rule X
after not ! must match fixed sequences of characters". Without them the
lookahead has a fixed length and needs no real parse.

A kind 3 rule is only allowed directly after the !, not called from inside a
sequence. The matcher tries alternatives only at the top level. Inside a
sequence it takes the first alternative of a called rule that matches and does
not go back to try another.

3. Parsing (src/main/c/parts/yaep.c)
------------------------------------

To the Earley parser, |!Nkw_else looks like an empty nonterminal flagged
is_not_operator. Normally the parser steps over an empty symbol for free. For a
not operator it first calls blocked_by_lookahead, which calls has_lookahead:

  - has_lookahead strips the |!N and finds the real kw_else symbol with
    symb_find_by_repr.
  - match_not_rule then matches it against the input from the current position:
      a terminal must equal the next input character,
      a charset is tested against its first set,
      a rule tries each alternative in turn, walking its terms one input
      position at a time.
  - If any alternative matches, the lookahead exists. The marker is blocked
    and that dotted rule dies.
  - If none matches, the parser moves the dot past the marker without
    consuming input.

nullable_here covers a rule that becomes empty only through a not operator.
Eg G = 'a' | !'x'. is empty unless the next character is x.

Example: test 035
-----------------

Input: if a if b x;else y;elsewhere;

  - After x; the inner if could take the "no else" branch |!Nkw_else. The
    input ahead is "else " and the space is in ~['a'-'z'], so kw_else
    matches. That branch is blocked, the inner if must take -'else ', stmt,
    and the dangling else binds to the closest if.
  - The outer if's "no else" branch sees "elsewhere". 'else' matches but w is
    not in ~['a'-'z'], so kw_else fails and the branch goes through.
  - call on "elsewhere" makes the same check, so call = elsewhere is allowed
    even though the word starts with "else".

The lookahead sees kw_else's raw characters, so any - marks on its parts make
no difference. kw_else itself never appears in the output, because the marker
rule is empty.
